# Проверка паритета Pine ↔ Rust

`aphelion_parity.py` (только стандартная библиотека Python 3.9+) пересчитывает по OHLC из CSV-выгрузки
TradingView всё то же, что считают скрипты, и сравнивает с колонками их графиков:
Mean, R, зоны, градацию g, подсветку X, X, COMBO, setup Aphelion proxy и (по желанию) вход 1h по 5m.

Формулы в скрипте портированы из Rust-крейта `aphelion` (`src/`, ранее код `crypto-markets-extractor`). Они проверены **побитово** на
синтетических рядах (5 seed × 5000 баров, плюс SMC на 2 × 6000 баров 5m) против копий исходных
Rust-функций. Поэтому совпадение с ним означает совпадение с Rust.

## 1. Выгрузка из TradingView

1. Откройте график инструмента, например `BINANCE:SOLUSDT.P` на 1h (биржа и тип контракта должны
   совпадать с данными, с которыми сравниваете).
2. Добавьте на график **только один** скрипт: `pine/aphelion.pine` или `pine/aphelion_proxy_long.pine`. У обоих есть
   колонки `Mean` и `R`, а при одинаковых именах берётся первая колонка.
3. Прокрутите график влево, чтобы загрузилась вся нужная история (≥ 1500 баров).
4. Меню графика (стрелка рядом с названием раскладки) → **Export chart data…** → выберите график
   с индикатором, формат времени **UNIX timestamp** → Export. В CSV будут `time,open,high,low,close`
   и все plot-колонки скрипта. Служебные колонки (`R`, `Z`, `G sell`, `X sell`, `Bar index`, …) видны
   только в Data Window, но в выгрузку тоже попадают. **Проверьте это на первой выгрузке**: если
   колонок нет, временно поменяйте у этих `plot` параметр `display = display.data_window` на
   `display.all`.

Выгрузку и сам CSV в репозиторий не коммитим (`*.csv` в `.gitignore`).

## 2. Запуск

```bash
python3 parity/aphelion_parity.py --selftest                    # синтетика, аналоги Rust-тестов
python3 parity/aphelion_parity.py export_x.csv                  # pine/aphelion.pine
python3 parity/aphelion_parity.py export_proxy.csv --mode proxy # pine/aphelion_proxy_long.pine (setup)
# вход 1h по 5m: в скрипте выключите "Require flow_exhaust", выгрузите 5m-график того же
# инструмента (только OHLC, тот же период + ≥ 70 баров до первого setup)
python3 parity/aphelion_parity.py export_proxy.csv --mode proxy --m5 export_5m.csv
```

Ключи: `--skip N` — не сравнивать первые N строк; `--rtol` — относительный допуск для чисел
(по умолчанию 1e-6, потому что TradingView может округлять выгрузку); `--keep-last` — не отбрасывать
последнюю строку (по умолчанию она отбрасывается как формирующийся бар); `--dump OUT.csv` —
записать пересчитанные ряды. Код выхода: 0 — всё совпало, 1 — расхождение, 2 — плохой вход.

## 3. Как читать результат

- `Bar index` первой строки ≠ 0 — выгрузка начинается не с первого бара графика. SuperSmoother
  засеян другим баром, прогрев сдвинут; используйте `--skip 1500`.
- Расхождение во флагах на единичных барах при `OK` у Mean/R обычно означает пограничный случай
  (`|close − Mean|/R` ровно у порога, g у 15). Посмотрите `--dump` и колонку `Z`/`G` на этом баре.
- Если все флаги сдвинуты на 1 бар, значит в выгрузку попал формирующийся бар (уберите `--keep-last`)
  или скрипт стоит на другом таймфрейме.
- Проверка `Entry` покрывает только вариант 1h без flow_exhaust: Python не видит внутрибаровые
  ограничения TradingView (старые бары без 5m-данных дают «no 5m data» в Pine).
- flow_exhaust по паритету не проверяется: в Pine это приближение, у сервера — реальная taker-дельта.

## 4. Сверка с данными сканера

Сканер `crypto-markets-extractor` может выгрузить кандидатов X своего исследования (LONG, 1h или 4h,
бары собраны из 5m Binance USDT-M): `t` — время закрытия сигнального бара (мс), `dist_c` —
`(Mean − close)/R`, `bx`/`bc` — прошёл ли он как X / COMBO. Команда описана в документации сканера.
Строка с `bx=1` и временем `t` соответствует LONG X в Pine на баре, который открылся в `t − 1h`;
`dist_c` должен совпадать со значением `−Z` этого бара. История у Rust начинается с начала выгрузки,
у TradingView — со своего первого бара, поэтому сравнивайте бары, у которых обе стороны имеют
≥ 1500 баров истории.
