# aphelion

**Aphelion** — наш индикатор возврата к среднему: Mean = SuperSmoother от hlc3, R = SuperSmoother
от true range, зоны `Mean ± k·R`, подсветка и метки X, подтверждения COMBO и сигнал proxy long.
В репозитории только формулы и параметры, рыночных данных (CSV, выгрузок, значений по барам) нет.

В репозитории две реализации одной модели:

| Путь | Что это |
|---|---|
| `Cargo.toml`, `src/` | Rust-крейт `aphelion` (edition 2024, без зависимостей): чистые вычисления без I/O |
| `pine/aphelion.pine` | Индикатор TradingView: Mean и зоны-ленты, подсветка X, метки X, COMBO, RSI, MACD, дивергенций, таблицы, алерты |
| `pine/aphelion_proxy_long.pine` | Правило Aphelion proxy long: setup на 1h/4h, вход после 5m sweep + CHoCH (1h) или на следующем открытии (4h), фильтр flow_exhaust (приближение), алерты |
| `parity/` | Проверка паритета Pine ↔ Rust без Rust: Python-скрипт (stdlib) и инструкция по выгрузке из TradingView |

## Rust-крейт

Все функции работают с закрытыми барами одного таймфрейма и не заглядывают вперёд (сигнал на баре
`i` использует только бары `..=i`). Сетевых запросов, часов, файлов и конфигурации в крейте нет.

| Модуль | Содержимое |
|---|---|
| `zones` | `Tf` (high/low/close + привязка к базовым барам), `Ind` (Mean, R), `BasisKind`, `DevKind`, `make_ind`, `done_map`, лестница `LADDER`, `ZONE_NAMES`, `SS_PERIOD`, `OUTER_K` |
| `indicators` | `ema`, `wilder`, `true_range`, `atr`, `rolling_mean_std`, `ss_step`, `supersmoother`, `supertrend_line`, `pivots` |
| `oscillators` | `Aux`: RSI(14), гистограмма MACD(12,26,9), ATR(14), дивергенции, RSI MA, Supertrend и флаги (`zone_flag`, `macd_flag`, `xma_flag`, `st_flip_flag`, …) |
| `x` | X: `zones`, `stoch_mix`, `gradation`, `band`, `repeat_filter`, `x_events`, `combo_events`, `signals`; константы `GRAD_*`, `START_R`, `ZONE_R`, `REPEAT_*`, `COMBO_LOOKBACK` |
| `combo` | COMBO-прокси: `COMBOS` (`outer_rsi_macd` = индекс 1), `ComboFlags`, `combo_flags`, `combo_step` (взвод «первый сигнал на выход»), `combo_events`, `macd_signal`, `windowed_any`, `WARM_BARS`, `WINDOW` |
| `smc` | 5m sweep + CHoCH: `Hlc` (срезы high/low/close), `smc_ok`, `smc_confirm`, `smc_entry`, `SMC_*` |
| `flow` | `taker_delta`, `flow_exhaust` |
| `live` | Работа по свечам: трейт `Candle` и `Bar`, `build_tf`, `Columns`, скользящие уровни `Levels`, `zone_above_mean`, сканер `long_scan` (Aphelion proxy long), `MIN_BARS`, `PROXY_COMBO` |

Подключение (зависимость фиксируется ревизией):

```toml
aphelion = { git = "https://github.com/mattaku5hi/aphelion.git", rev = "<sha>" }
```

Пример: зона последнего закрытого 1h бара в R над Mean.

```rust
use aphelion::{Bar, live::zone_above_mean};

const H: i64 = 3_600_000;
fn zone(bars: &[Bar], now_ms: i64) -> Option<f64> {
    zone_above_mean(bars, H, now_ms) // None: < 450 баров, последний бар не последний закрытый, R <= 0
}
```

Проверки: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
Код перенесён из `crypto-markets-extractor` без изменения арифметики; там же лежит тест
`aphelion_parity_tests`, который сравнивает FNV-дайджесты битовых значений всех выходов на
синтетических рядах с эталоном, записанным до выноса кода.

## Установка в TradingView

1. Откройте график (для Aphelion proxy: 1h, или 4h для варианта 4h).
2. Внизу **Pine Editor** → **Open** → **New blank indicator**, удалите шаблон и вставьте
   содержимое `pine/aphelion.pine` (или `pine/aphelion_proxy_long.pine`).
3. **Save**, затем **Add to chart**.
4. Прокрутите график влево. Скрипту нужно ≥ 400 баров истории (прогрев), а для стабильного
   SuperSmoother лучше ≥ 1000. Подписки TradingView дают 5–20 тыс. баров, этого хватает.

## Модель (формулы)

- **Mean** = SuperSmoother(200) от hlc3, **R** = SuperSmoother(200) от true range. SuperSmoother Элерса,
  2 полюса: `w = √2·π/200`, `a = e^−w`, `c2 = 2a·cos w`, `c3 = −a²`,
  `y = (1 − c2 − c3)·x + c2·y[1] + c3·y[2]`; на первых двух барах `y = x[0]`. TR первого бара = high − low.
- **Зоны** (в R от Mean): π (внутренняя), 2.415π − 2 ≈ 5.587 (малая), 2.415π ≈ 7.587 (центральная),
  ≈ 9.587 (глубокая), ≈ 11.587 (доп.).
- **Градация** по сторонам: `S` = стохастик close в диапазоне high/low за 21 бар в лог-ценах
  (для покупок `100 − S`). `g = 0.75·g[1] + 1.0·(S − 76)` без клиппинга; пока S нет (первые 20 баров), g = 0.
- **Подсветка X**: включается только если `|open − Mean| ≥ π·R` в сторону растяжения и `g > 15`, затем
  держится, пока `g > 15`.
- **X**: первый бар после конца подсветки, если `|close − Mean| ≥ 5.587·R` в сторону растяжения
  (SHORT — выше Mean, LONG — ниже). Антиповтор: следующий X той же стороны проходит, только если прошло
  ≥ 5 баров **или** цена (close к close) ушла ≥ 1% от предыдущего X. Не раньше бара 400.
- **COMBO**: X, у которого за последние 10 баров (включая бар X) было ≥ 2 из 3 подтверждений:
  RSI(14, Уайлдер) > 70 / < 30 (с тем же антиповтором 5 баров/1%), сигнал MACD(12,26,9) против движения
  (разворот гистограммы или её переход через 0, тот же антиповтор), регулярная дивергенция RSI
  (пивоты RSI по 5 баров с каждой стороны, расстояние 5–60 баров, флаг на баре подтверждения).
- **Aphelion proxy long (`outer_rsi_macd`)**: за последние 3 бара было закрытие ниже `Mean − 7.587·R`
  (или бычья дивергенция с пивотом за этой зоной), RSI < 30 и разворот/пересечение MACD вверх.
  Берётся первое событие на выход за зону: правило перевзводится, когда условие зоны пропало на 3 бара.
  Не раньше бара 400.

### Внешний вид

- **Зоны — ленты.** Продажи — красные оттенки над Mean, покупки — зелёные под Mean. Между соседними
  уровнями (Mean → π → 5.587 → 7.587 → 9.587 → 11.587) заливка `fill()`; внутренние ленты бледнее,
  внешние плотнее. Цвет каждого уровня — смесь «внутреннего» и «внешнего» цвета стороны. Линии ±7.587 и
  глубже толще. Mean — тонкая полупрозрачная серая линия.
- **Подсветка X** по умолчанию — точки на уровне Mean ± π·R (по стороне подсветки). Варианты: подкраска
  ленты Mean…π, фон (`bgcolor`, как раньше) или выключено. Всё рисуется только на закрытом баре.
- **Метки** складываются стопкой от бара наружу: ближе всего SHORT X / LONG X и COMBO, затем RSI
  (жёлтая), MACD (синяя), затем точка дивергенции (красная над баром — медвежья, зелёная под баром —
  бычья). Шаг стопки — `шаг × ATR(14)` в цене, поэтому при сильном отдалении графика метки могут
  касаться друг друга: увеличьте шаг или уменьшите размер. У каждой метки есть подсказка (наведите курсор):
  значение RSI, расстояние close от Mean в R, а у COMBO — какие подтверждения были в окне (✓/✗).
- **Таблица зон** (справа сверху), по сторонам «Продажи» и «Покупки», по текущему бару: зона (расстояние
  close от Mean в R и интервал лестницы), градация g относительно порога подсветки (`g / 15`, шкала
  из 5 клеток, 100 % = подсветка может гореть), состояние («Подсветка X» / «Растяжение» при ≥ π·R /
  «Нейтрально»), «X возможен?» (да, если подсветка горит и close уже за 5.587·R: X будет на первом баре
  после конца подсветки).
- **Таблица таймфреймов** (справа снизу), для ТФ 1 и 2 (по умолчанию 1h и 4h) через `request.security`:
  последний X и сколько баров назад, RSI (SHORT > 70, LONG < 30), последняя дивергенция и её возраст.
  ТФ не меньше графика читается по последнему **закрытому** бару (`[1]` + `lookahead_on`, без
  перерисовки), более мелкий ТФ — по последнему бару внутри бара графика. Модель на этих ТФ считается
  целиком, с тем же прогревом 400 баров уже этого ТФ. Таблицы выключаются, но `request.security`
  считается всегда (на время выполнения это влияет мало).

### Метки и COMBO: соответствие условий

Метки RSI/MACD/дивергенции рисуются по **тем же флагам**, которые COMBO считает в окне 10 баров
(`src/x.rs` `combo_events`):

| Метка | Флаг | Условие |
|---|---|---|
| RSI над баром / под баром | `rsiSell` / `rsiBuy` | RSI(14, Уайлдер) > 70 / < 30 после антиповтора (5 баров или 1 % цены) |
| MACD | `macdSell` / `macdBuy` | `macd_signal`: разворот гистограммы MACD(12,26,9) от экстремума против движения или её переход через 0, после антиповтора |
| Точка дивергенции | `divSell` / `divBuy` | регулярная дивергенция между соседними пивотами RSI (5 баров с каждой стороны, 5–60 баров между ними); точка стоит на баре **подтверждения** пивота (пивот + 5), где флаг становится известен |
| SHORT X / LONG X | `xSell` / `xBuy` | первый бар после конца подсветки при \|close − Mean\| ≥ 5.587·R, антиповтор |
| COMBO SHORT / LONG | `comboSell` / `comboBuy` | X и ≥ 2 разных подтверждения за 10 баров, включая бар X |

Фильтр «только при \|close − Mean\| ≥ π·R» прячет метки RSI/MACD/дивергенции у Mean, где их очень
много; на COMBO он не влияет. При 0 видны все подтверждения, и тогда каждый COMBO объясняется метками
слева от него в пределах 10 баров. Не больше 500 меток на скрипт: на длинной истории старые удаляются.

### Автомасштаб

TradingView подгоняет шкалу цены под **значения plot-ов** на видимых барах. Значение `na` в автомасштабе
не участвует; plot-ы с `display = display.data_window` (служебные колонки паритета) и `display.none` шкалу
не меняют (документация Pine: Plots → display, FAQ → Indicators); `bgcolor` цены не имеет. Поэтому:

1. По умолчанию всегда рисуются зоны до ±7.587·R.
2. Более глубокие уровни (±9.587, ±11.587) в режиме `Only near price` имеют значение только на тех барах,
   где high (продажи) или low (покупки) за последние 6 баров подошли к уровню ближе 1·R, на остальных
   барах plot равен `na`. Глубокая лента появляется, только когда цена к ней подходит, и раздвигает шкалу
   максимум на ~1·R за свечи. `Always` возвращает прежнее поведение, `Off` — без глубоких уровней.
3. Подсветка X по умолчанию — точки на уровне Mean ± π·R, а не фон.
4. Значения зон по умолчанию не выводятся на шкалу цены (меньше подписей справа). Это не влияет на
   масштаб, только на подписи.

Метки (`label.new`) стоят в пределах нескольких ATR от свечи. Линии/боксы для глубоких зон не
используются: участие рисунков в автомасштабе в документации не описано. Если шкалу всё же растягивает
другой индикатор: правый клик по шкале → **Scale price chart only**.

## pine/aphelion_proxy_long.pine: входы и логика

Поставьте скрипт на **1h** график (вариант по умолчанию) или на **4h** с вариантом
«4h: entry at the next open». Если таймфрейм не совпадает, справа появится предупреждение.

1. **Setup** (бледная метка `Aphelion setup` под сигнальным баром, алерт `Aphelion proxy setup`): закрытый бар
   выполнил `outer_rsi_macd` LONG.
2. **Вход 1h** (метка `Aphelion LONG entry`, алерт `Aphelion proxy entry`): на 5m барах, начиная с последнего 5m
   бара сигнального часа и до 12 баров после закрытия часа (`SMC_WAIT`), ищется первый бар `b`, на котором:
   самый низкий low `x` за последние 12 баров (`SMC_LOOK`) ниже минимума 48 баров до него (`SMC_LIQ`,
   sweep), а close бара `b` выше максимума high 6 баров перед `x` (`SMC_SWING`, CHoCH). Вход — открытие
   следующего 5m бара. Метка ставится на баре графика, который содержит этот 5m бар. Если
   подтверждение пришло на последнем 5m сигнального часа, метка setup превращается в метку входа.
3. **Вход 4h** (`Aphelion 4h LONG next open`): сразу по закрытию сигнального 4h бара, без 5m-шага.
4. **flow_exhaust** (вкл. по умолчанию): на момент входа дельта потока за 4 ч < 0 (продают, то есть
   по ходу падения), а за последний час она больше дельты 4 ч (продажи слабеют). Дельта = (покупки −
   продажи) / оборот. **Это приближение**: сервер считает дельту по реальному taker-buy объёму биржи
   (1m свечи Binance), а в данных TradingView его нет. В Pine объём 1m свечи (× close) целиком
   считается покупкой, если свеча зелёная, продажей, если красная, и нулём для доджи. Если в окне не
   хватает 1m-баров, сигнал пропускается («flow ?»), как и на сервере при неизвестном покрытии.
5. Пропущенные setup помечаются серым: `flow ✗`, `flow ?`, `no SMC`, `no 5m data`.

Входы: вариант, параметры setup (200, 400, 2.415π, окно 3, RSI 14 < 30, MACD 12/26/9, пивот 5,
дивергенция 5–60), 5m-подтверждение (ТФ 5, 12 / 48 / 6, ожидание 12), flow (вкл., ТФ 1, окна 4 ч и 1 ч),
ленты Mean / −π / −5.587 / −7.587 (лестница целей 40/40/20 бумажной стратегии; тот же вид, что у
`aphelion.pine`: заливки между уровнями, цвета внутр./внеш., прозрачность, толщина), пометка пропусков.

Алерт входа: с частотой **Once per bar** он срабатывает сразу после закрытия подтверждающего 5m бара
(условие использует только закрытые 5m бары). С частотой **Once per bar close** — на закрытии часа.

Только на сервере (в Pine нет): лимиты позиций и экспозиции, теневой фильтр F2 по объёму, выходы,
доливки, таймауты, проверка «сигнал устарел».

## Что не входит в модель

- Значение градации g служит только для подсветки и не выводится как отдельная шкала.
- Быстрые серии X на 4h (X через 1–3 бара) отсекаются антиповтором.
- Окно COMBO фиксированное (10 баров). RSI, MACD и дивергенция — наши подтверждения; нужно любые два.
- Supertrend и MTF-тренд в индикатор не входят: на X/COMBO они не влияют. Таблицы — только справка.

## Где Pine не совпадает с Rust точно

- **Начало истории.** Rust засевает SuperSmoother первым баром своих данных: в живом сканере это скользящее
  окно ~500 баров 1h, пересчитываемое каждый час; в бэктесте это `--from`. Pine засевает первым баром
  графика. Затухание стартовой ошибки ≈ 0.978ⁿ: после 400 баров ~1e−4 от начального отклонения,
  после ~1000 баров ~1e−10. Поэтому на первых сотнях баров после прогрева Mean/R могут немного
  отличаться от сканера, и сигналы у самых порогов тоже.
- **Прогрев.** Сканер требует ≥ 450 закрытых баров (`MIN_BARS`) и считает сигналы с индекса 400 своего
  окна. В Pine сигналы идут с `bar_index ≥ 400` от начала графика.
- **Глубина внутрибаровых данных.** `request.security_lower_tf` отдаёт ограниченное число внутрибаровых
  баров (зависит от подписки). На старой истории у Aphelion proxy будут `no 5m data` / `flow ?`, хотя сервер
  вошёл бы. Setup при этом считается без ограничений.
- **flow_exhaust** — приближение по цвету свечей, а не taker-дельта (см. выше).
- **Данные.** Сканер и бэктест берут Binance USDT-M (бэктест собирает 1h из 5m). Используйте
  `BINANCE:<SYMBOL>.P`. У других бирж или у спота свечи иные.
- **Плавающая точка.** `exp`/`cos`/`log` на серверах TradingView могут отличаться от libm в последнем
  бите. На сигналы это влияет только при значении ровно на пороге.
- **Подписи.** Не больше 500 меток на скрипт (самые старые удаляются).
- Формирующийся бар: линии Mean и зон двигаются вместе с ним (как у любого индикатора), подсветка,
  метки и алерты появляются только после закрытия. Исключение — вход Aphelion proxy 1h, он может появиться
  внутри часа, но только по закрытым 5m барам.

## Паритет

См. `parity/README.md`: выгрузка графика с индикатором в CSV и
`python3 parity/aphelion_parity.py export.csv`. Скрипт пересчитывает всё по OHLC и сравнивает с колонками
Pine. Сам Python-порт проверен побитово против исходных Rust-функций на синтетических данных.

## Что проверить на TradingView (офлайн не проверялось)

1. Оба скрипта компилируются без ошибок (Pine v6: синтаксис, типы, `request.security_lower_tf` с
   кортежем, методы массивов/меток).
2. В выгрузке CSV есть колонки `R`, `Z`, `G sell`, …, `Bar index` (они `display.data_window`), и
   `parity/aphelion_parity.py` даёт `PARITY OK` на 1h и 4h нескольких монет.
3. Aphelion proxy: метки входа появляются на свежей истории (есть 5m/1m внутрибаровые данные), а на старой
   истории дают `no 5m data`/`flow ?`. Алерт входа с частотой «Once per bar» срабатывает внутри часа.
4. Нет ошибок `max_bars_back` или лимитов времени выполнения на длинной истории.
5. `aphelion.pine`: шкала цены определяется свечами (глубокие ленты появляются только у цены), ленты и
   цвета читаются на тёмной и светлой теме, метки не наезжают друг на друга на обычном масштабе 1h,
   таблицы справа сверху/снизу не перекрывают последние свечи, значения таблицы ТФ совпадают с метками
   на графике этого ТФ.
